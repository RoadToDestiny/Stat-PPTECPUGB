# Backend 1: загрузка партий и анализ Stockfish

Ответственный: **Бэкендер 1**  
Тема исследования: *Прогнозирование вероятности шахматных ошибок на основе градиентного бустинга*

---

## 1. Назначение модуля

Модуль реализует первые три этапа подготовки данных:

1. Подготовка Python-окружения и общего интерфейса для Stockfish.
2. Загрузка, чтение, проверка и фильтрация партий из Lichess Open Database.
3. Фиксация версии Stockfish, глубины анализа и формата оценок для
   последующего формирования датасета.

Результатом работы модуля является проверенный PGN-файл с партиями,
соответствующими критериям исследования, а также единый интерфейс получения
оценок позиций для Бэкендера 3.

## 3. Этап 1. Подготовка окружения и настройка Stockfish

### Зависимости Python

Установка выполняется из корня репозитория:

```powershell
python -m pip install -r bac1\requirements.txt
```

В `requirements.txt` входят:

- `python-chess` — работа с доской, PGN и UCI-движком;
- `requests` — скачивание PGN из Lichess Open Database;
- `zstandard` — чтение архивов Lichess в формате `.zst`;
- `pytest` — запуск тестов.

### Установка Stockfish

Stockfish устанавливается отдельно от Python-зависимостей. Исполняемый файл
должен быть доступен через `PATH`, либо его путь передаётся явно через
`StockfishConfig(executable=...)`.

Проверка запуска из Python:

```powershell
python -c "from bac1.src.stockfish_engine import StockfishEngine; print(StockfishEngine().verify())"
```

Метод `verify()` запускает движок, анализирует начальную позицию и возвращает
идентификатор Stockfish. Точный идентификатор следует записать в
`AnalysisConfig(stockfish_version=...)` для воспроизводимости эксперимента.

## 4. Этап 2. Загрузка и фильтрация партий

### Проверяемые данные

Перед сохранением партии выполняются следующие проверки:

- наличие стандартных PGN-заголовков;
- наличие `WhiteElo`, `BlackElo` и `TimeControl`;
- отсутствие ошибок парсинга;
- корректность и легальность всех ходов основной линии;
- соответствие выбранному контролю времени;
- соответствие диапазону рейтингов;
- соответствие минимальной и максимальной длине партии.

Поддерживаются обычные PGN-файлы, `.gz` и архивы Lichess `.zst`.

### Обязательные заголовки PGN

```text
Event, Site, Date, Round, White, Black, Result,
WhiteElo, BlackElo, TimeControl
```

Контроль времени Lichess разбирается в формате `base+increment`, например:
`600+5` означает 600 секунд основного времени и 5 секунд добавления за ход.

### Пример фильтрации

```python
from pathlib import Path

from bac1.src.pgn_pipeline import FilterCriteria, filter_pgn

criteria = FilterCriteria(
    min_elo=1600,
    min_base_seconds=600,
    min_full_moves=10,
)

stats = filter_pgn(
    Path("data/raw/lichess_games.pgn.zst"),
    Path("data/raw/filtered_games.pgn"),
    criteria,
)
print(stats)
```

`filter_pgn()` возвращает статистику:

- `read` — прочитано партий;
- `accepted` — принято после всех проверок;
- `rejected` — отклонено по критериям фильтрации;
- `invalid` — отклонено из-за ошибок PGN или нелегальных ходов.

## 5. Этап 3. Фиксация параметров Stockfish

Параметры анализа собраны в [analysis_config.py](src/analysis_config.py):

| Параметр | Значение по умолчанию | Назначение |
|----------|-----------------------|------------|
| `stockfish_version` | `Stockfish 17` | Версия движка, используемая в эксперименте |
| `depth` | `18` | Глубина анализа в полуходах |
| `mate_score_cp` | `100000` | Числовое представление матовой оценки |

Интерфейс `StockfishEngine.analyze(board)` возвращает:

```python
{
    "score_cp": 35.0,
    "is_mate": False,
    "mate_in": None,
    "depth": 18,
}
```

Оценка всегда выражается с точки зрения белых. Для матовых позиций:

- `is_mate` устанавливается в `True`;
- `mate_in` содержит число ходов до матовой позиции, если оно доступно;
- `score_cp` получает значение `100000` или `-100000`.

Флаг `is_mate` должен сохраняться в датасете, чтобы Бэкендер 3 мог исключить
матовые позиции из формирования целевой переменной.

## 6. Совместимость с `bac3`

Отфильтрованный файл `filtered_games.pgn` передаётся в модуль Бэкендера 3
для формирования признаков и целевых переменных. Оценки Stockfish должны
использоваться следующим образом:

- `eval_before` — оценка позиции до хода;
- `eval_after` — оценка позиции после хода;
- `is_mate_eval` — признак матовой оценки;
- `eval_loss` и `is_error` — вычисляются после приведения оценок к
  перспективе игрока, который сделал ход.

Формулы, состав признаков и требования к объёму датасета описаны в
[`bac3/README.md`](../bac3/README.md).
